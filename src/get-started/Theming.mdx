# 테마 커스터마이즈

`ispark-ui`는 두 종류의 변경 지점을 제공한다. **색상**은 CSS 변수, **구조**는 부모 클래스로 specificity 끌어올리기.

<table>
  <thead>
    <tr><th>종류</th><th>변경 방법</th><th>자유도</th><th>런타임 전환</th></tr>
  </thead>
  <tbody>
    <tr><td><strong>색상</strong></td><td><code>:root</code> CSS 변수 덮어쓰기</td><td>무조건 OK</td><td>가능 (즉시 반영)</td></tr>
    <tr><td><strong>구조 (간격·radius·border)</strong></td><td>부모 클래스로 selector 확장</td><td>가능, import 순서 주의</td><td>불가 (빌드 타임)</td></tr>
    <tr><td><strong>폰트·shape·spacing 토큰</strong></td><td>SCSS 변수 (라이브러리 빌드 시점)</td><td>불가</td><td>불가</td></tr>
  </tbody>
</table>

라이브러리 컴포넌트는 모두 `<style scoped>`로 빌드되어 `.ui-accordion-trigger[data-v-xxxxx]` 형태로 hash 속성이 박힌다. 단순히 `.ui-accordion-trigger { ... }`만 쓰면 specificity가 낮아 덮어쓰기 실패한다.

## 빠른 시작 — 5줄로 브랜드 컬러 적용

```scss
// app.scss — ispark-ui style.css 뒤에 로드
:root {
  --color-primary: #ff7518;
  --color-primary-hover: #e5660f;
  --color-primary-bg: #fff4eb;
  --color-primary-rgb: 255, 117, 24; // tint 배경 계산용 (필수)
}
```

primary 한 톤만 바꿔도 Button/Select/Input focus ring/Tab indicator/Pagination active/Badge primary tint/Modal accent까지 일괄 반영. 다른 변수는 그대로 두고 시작해도 충돌 없음.

## 1. 색상 — `:root` CSS 변수

`ispark-ui/style.css`가 `:root`에 모든 테마 변수를 노출한다. 컨슈머가 같은 `:root` 또는 더 specific한 selector(예: `.app-theme`)에서 덮어쓰면 즉시 반영.

```scss
@import 'ispark-ui/style.css';

:root {
  --color-primary: #ff7518;
  --color-primary-hover: #e5660f;
  --color-primary-bg: #fff4eb;
  --color-primary-rgb: 255, 117, 24;

  --color-danger: #c73e07;
}
```

## 2. 구조 — 부모 클래스로 덮어쓰기

`<style scoped>`의 hash specificity(`0,2,0`)에 맞추려면 부모 클래스를 한 칸 끼워 selector를 같은 specificity로 만든다.

```vue
<!-- 컨슈머 App.vue 루트 -->
<template>
  <div class="app-theme">
    <!-- 모든 ispark-ui 컴포넌트는 이 안에서 렌더 -->
  </div>
</template>
```

```scss
// 컨슈머 SCSS — ispark-ui 다음에 로드
.app-theme {
  .ui-accordion-trigger { padding: 20px 24px; }
  .ui-accordion-item    { border-bottom-style: dashed; }
  .ui-tab-item.is-active::after { height: 3px; }
  .ui-button { letter-spacing: 0.02em; }
}
```

**왜 동작하나** — 라이브러리는 `.ui-accordion-trigger[data-v-xxxxx]` (specificity `0,2,0`), 컨슈머는 `.app-theme .ui-accordion-trigger` (specificity `0,2,0`). 동률일 땐 **뒤에 로드된 쪽이 이긴다**.

## 3. Import 순서 (중요)

```ts
// ❌ 잘못 — 라이브러리가 뒤에 와서 컨슈머 override를 덮어버림
import './app-theme.scss'
import 'ispark-ui/style.css'

// ✅ 올바름
import 'ispark-ui/style.css'
import './app-theme.scss'
```

## 4. 실전 레시피

### 4-1. 회사 톤 변경 (한 파일에 모음)

```scss
// app-theme.scss — 한 파일에 색·폰트·미세 구조 다 담음
:root {
  // 브랜드 컬러 (오렌지 톤)
  --color-primary: #ff7518;
  --color-primary-hover: #e5660f;
  --color-primary-dark: #c73e07;
  --color-primary-dark-hover: #a83306;
  --color-primary-rgb: 255, 117, 24;
  --color-primary-bg: #fff4eb;

  // semantic
  --color-danger: #dc2626;
  --color-success: #15803d;

  // 텍스트 톤 (살짝 더 진하게)
  --color-text-primary: #1f2937;
  --color-text-heading: #0f172a;
}

.app-theme {
  // 폰트
  font-family: 'Spoqa Han Sans Neo', sans-serif;

  // 컴포넌트 미세 조정
  .ui-button { font-weight: 600; letter-spacing: 0.01em; }
  .ui-accordion-item { border-bottom-color: #eee; }
}
```

### 4-2. 다크 모드 후크 (`data-theme="dark"`)

```html
<!-- 컨슈머 root -->
<html data-theme="light">
```

```scss
// 라이트 (기본 :root는 이미 라이브러리가 설정)
:root {
  --color-bg-elevated: #ffffff;
  --color-background: #f4f7f9;
  --color-text-primary: #4d5462;
  --color-text-heading: #1e2124;
  --color-border: #dce4e9;
  --color-border-light: #ecf0f3;
}

// 다크
[data-theme="dark"] {
  --color-bg-elevated: #1f2026;
  --color-background: #1a1b1f;
  --color-surface: #25272d;

  --color-text-primary: #d4d3ca;
  --color-text-heading: #f5f4ed;
  --color-text-secondary: #8a8a82;
  --color-text-muted: #6b6d75;

  --color-border: #2a2c33;
  --color-border-light: #25272d;

  // primary는 다크에서 살짝 더 밝게 (가독성)
  --color-primary: #6b8fe8;
  --color-primary-hover: #88a3eb;
}
```

```ts
// 토글 트리거 (Pinia/composable 자유)
document.documentElement.dataset.theme =
  document.documentElement.dataset.theme === 'dark' ? 'light' : 'dark'
```

## 7. 안 되는 것 (의도된 한계)

- **`<style scoped>` 내부의 미세 디테일**까지는 못 건드림. 예: `.ui-accordion-content`의 `animation` 이름. 필요하면 같은 keyframe을 부모 스코프에서 재정의.
- **컴포넌트 props로 노출되지 않은 동작**. 디자인 정책상 막아둔 것은 라이브러리에 요청.
- **`!important`는 마지막 수단**. 일단 부모 클래스 specificity로 해결되면 그쪽이 깨끗하다.

## 8. 다음 단계

- **디자인 토큰 export** — 현재 TS로 `Size`, `Shape`, `SelectSize` 등 prop 타입은 export 중. 향후 컬러/spacing 토큰도 TS 객체로 export 검토.
- **SCSS API** — `@use '@leechanyong/ispark-ui/styles' as ispark;` 형태로 `$color-primary`, `$spacing-md` 등을 직접 import할 수 있게 검토 중. 현 시점은 CSS 변수만.
- **다크 모드 빌트인** — 현재 `[data-theme="dark"]` 패턴은 컨슈머 작성. 향후 라이브러리 차원에서 dark preset 옵션 제공 검토.
